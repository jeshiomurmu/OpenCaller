## Open issues / blockers

1. **Repository visibility.** `jeshiomurmu/OpenCaller` is public, but the plan says private until v0.1. The owner decides (GitHub → Settings → Danger zone → Change visibility).
2. **MinIO distribution.** MinIO no longer publishes images and its repo is archived. The stack uses `cgr.dev/chainguard/minio:latest` (free tier, `latest` only, not pinnable) plus a static BusyBox for the healthcheck (`infra/docker/minio/Dockerfile`). It is verified in CI. Long term: pin a digest/paid tag, build from source, or move to an S3-compatible alternative (Garage/SeaweedFS) via an ADR before Phase 4.
3. **Compose is held at BOM 2026.06.01 (Compose 1.11.x).** Compose 1.12+ requires `compileSdk 37`, and `architecture.md` §2 fixes `compileSdk 36`. Raising compileSdk to 37 (targetSdk can stay 36) would allow current Compose; needs a decision/ADR.
4. **Lint `OldTargetApi` disabled.** Android 17 (API 37) is out; `targetSdk 36` is fixed by `architecture.md` §2. Revisit before the first Play release (Phase 15).
5. **Detekt 1.23.8 Gradle plugin** triggers Gradle 10/11 deprecation warnings (`ReportingExtension.file`, `Configuration.setVisible`). Detekt 2.0 is still alpha; upgrade when it is stable.
6. **Room 3.** Room 3.x exists but drops the SupportSQLite APIs that SQLCipher's `SupportOpenHelperFactory` plugs into, so the project stays on Room 2.8.5. Revisit when SQLCipher ships a Room 3 driver (needs an ADR).
7. **Gradle 9.8.1** is used for both builds. AGP 9.4.0 declares Gradle ≥ 9.6.0 (minimum and default 9.6.0).
8. **Agent sandbox limits** (informational): `dl.google.com`, `github.com`, `www.gnu.org` and `cgr.dev` are blocked and there is no KVM, so Android, emulator and LICENSE checks run only in CI. JVM modules (`core:common`, `core:model`, `core:phonenumber`, `core:testing`, proto mapping) and the backend were also run locally.
9. **`RedactingTree` location.** The spec puts it in `core:common`, but Timber is an Android library and `core:common` must not depend on Android. `LogRedactor` (the masking) is in `core:common`; the `Timber.Tree` wrapper is in `app` (`logging/RedactingTree.kt`). Move it into a small Android module if features need to plant it themselves.
10. **Wrong SQLCipher key wipes the DB.** Android's default `DatabaseErrorHandler` deletes a database file it cannot open. If the Keystore key is lost (e.g. a device restore without the key), the user's block rules and local data are recreated empty instead of being kept. Decide before Phase 3 whether to surface this (custom error handler + "reset local data" UX) or accept it.
11. **compileSdk 37 also holds back Navigation.** Navigation 2.10 needs `compileSdk 37` (same as issue 3), so Navigation Compose is pinned at 2.9.8.
12. **Default region.** Resolved in Phase 3: `DeviceHomeRegionProvider` (`core:telephony`) reads the SIM country, then the network country, then the locale.
13. **Tab naming.** `implementation_plan.md` says "Blocking"; P-01 and the app say "Protection". Pick one and align the docs before Phase 3.
14. **Derived colour roles.** `design.md` §2 doesn't define every Material 3 role (e.g. dark semantic containers, `surfaceContainer*`). These are derived by blending §2 tokens (`ColorScheme.kt`, `OpenCallerSemanticColors.kt`). A designer should confirm the result.
15. **Module types.** `core:phonenumber`, `core:testing` and `core:datastore` are JVM modules (no Android API needed), so they test without Robolectric. `core:database`, `core:designsystem` and `core:ui` are Android libraries.
16. **API 29 emulator night mode.** `cmd uimode night yes` from the shell has no effect on the API 29 image. `scripts/ci/emulator-smoke.sh` retries as root and then falls back to the persisted setting plus a reboot.
17. **Default SMS app role shows "Coming in a later update".** Resolved: Phase 6a for the default phone app (in-call service and dial pad), Phase 7a for the SMS app (the four components of `feature:messages` and `MainActivity`).
18. **Role changes kill the app process on API 36.** Granting or revoking `ROLE_CALL_SCREENING` (system dialog or `cmd role`, even with the don't-kill flag) ended the app process, which in instrumented tests is also the test process. TC-ONB-001, 003 (role held) and 005 therefore run in `scripts/ci/emulator-smoke.sh` via adb. The app copes (the step is persisted and onboarding resumes). Re-check on a physical Android 16 phone before Phase 3.
19. **Robolectric runs SDK 35, not 36.** Robolectric 4.17's Android 16 image needs Java 21 (`DefaultSdkProvider`); the project builds with JDK 17. Move tests to SDK 36 when the toolchain moves to Java 21 (needs a decision).
20. **TC-ONB-006 / 007 against the real surfaces.** Phase 3 added the caller ID card and the after-call notification. The emulator QA shows the overlay card (TC-BLK-009). `CallerIdTest` (Robolectric) covers the heads-up fallback and that nothing is posted without the notification permission. A manual pass with the overlay denied on a phone is still worth doing.
21. **Requested in context since 6b:** `WRITE_CONTACTS` (contact Save / favourite star), `READ_CALL_LOG`/`WRITE_CALL_LOG` (call log, default phone app only), `READ_PHONE_NUMBERS` (the in-call SIM chooser, issue 71); the dial pad's SIM picker uses them once granted. Since 7a the SMS permissions (`READ_SMS`, `SEND_SMS`, `RECEIVE_SMS`, `RECEIVE_MMS`, `RECEIVE_WAP_PUSH`) come with the default SMS app role and are never asked for on their own. `READ_PHONE_STATE` is requested from Settings since Phase 3 (issue 28). `architecture.md` §5 lists them for onboarding; add them with the screens that need them.
22. **Test fake duplicated.** `FakeAccessStatusSource` exists in three test source sets (onboarding, settings, app) because `core:testing` is a JVM module and `AccessStatusSource` lives in the Android `core:telephony`. Consider Android test fixtures later.
23. **Maven Central returned HTTP 403** for the Robolectric/Turbine POMs in one CI run (run 38871676332, 2026-10-16); the next run resolved them. Watch for repeats: the branch's Gradle cache is read-only, so new dependencies are downloaded on every run.
24. **Spam threshold semantics.** The Phase 3 spec fixes HIGH = 0.85 and MEDIUM = 0.6, so a higher threshold blocks *fewer* calls (the old `SpamThreshold` KDoc said the opposite and was rewritten). LOW = 0.4 is our choice (not in the spec); numbers listed from 0.4 up to the threshold show as Suspicious. Confirm LOW with the product owner.
25. **Hidden numbers (TC-BLK-007).** Android doesn't pass hidden-number calls to a call screening app that isn't the default phone app, so "Block hidden numbers" only takes effect while OpenCaller is the default phone app (possible since Phase 6a). The setting says so; device-only test (the emulator can't hide a number).
26. **Stubs until later phases:** resolved in Phase 9: `VerifiedBusinessLookup` reads the verified-business directory on the phone (debug QA marks still work). Resolved in Phase 5: the live lookup is real and reports are uploaded.
27. **After-call summary in screening-only mode is best effort.** Without the overlay, nothing keeps the process alive while the phone rings, so Android may kill it before the call ends and no summary is posted. As the default phone app (Phase 6a) Telecom keeps the in-call service bound for the whole call, so the after-call card is reliable there.
28. **Call status permission.** `READ_PHONE_STATE` (Android 12+) is requested from Settings → Permissions & roles ("Call status"), not in onboarding. Without it the card closes when the audio mode returns to normal, or after 90 s for silenced calls.
29. **Regex rules on Android.** The platform regex engine (ICU) can't be interrupted, so a runaway pattern keeps one of 4 daemon threads busy until it finishes (bounded by the 16-character input); the editor rejects slow patterns and a pattern that times out twice is skipped.
30. **"Not spam" from the after-call notification** adds an exact allow rule and queues a NOT_SPAM report. Revisit in Phase 5 once community scores exist (an allow rule also overrides the user's own later block rules for that number).
31. **Screening log retention** is 90 days, with no "clear history" action yet.
32. **Emulator memory.** The API 29 image ran `system_server` with a 16 MB heap and died mid-test once (run 38891529407); the CI emulators now get `ram-size: 4096M` and `heap-size: 512M`. Watch for repeats.

33. **STIR/SHAKEN (TC-BLK-014)** is read on API 30+ and mapped to the card ("Verified by carrier" / "Possibly spoofed"). The emulator can't sign calls, so it is tested at the mapping level only (`DeviceScreeningTest`); check on a carrier that signs calls.
34. **First calls.** libphonenumber loads each country's metadata on first use. `ScreeningWarmUp` loads the home country at app start and on a SIM change, but the first call from a rarely seen country can still take tens of ms (about 70 ms observed for a cold country before the warm-up). That stays far inside the 1,500 ms budget. Opening another encrypted database connection costs about 0.5 s (SQLCipher derives the key per connection), so the engine reads its lists one after another; a raw 256-bit key would skip the derivation (changes `core:database`, needs a decision).
35. **Seed spam list is empty.** `assets/spam_list/seed.csv` has only comments; since Phase 5 the list comes from the server (daily update). Builds without a server (the alpha) have no spam list, only the user's rules and settings.
36. **Decision latency on CI emulators (BUG-0002).** Debug builds log each decision's step durations and the QA script prints the slowest. The app's own steps take 0–16 ms; Android's contacts lookup (`ContactsContract.PhoneLookup`, a call into the system contacts provider, required before any block because contacts always ring) takes 24–58 ms on the slow decisions, so p95 sits at 46–50 ms against a "< 50 ms" gate. Decided 2026-10-16 (owner asked to fix the failing check; option (a) of the three proposed): CI gates the app's own time (decision minus the contacts lookup) at p95 < 50 ms and the emulator total at p95 < 100 ms; the exit criterion's total < 50 ms is measured on a physical phone. Not chosen: an in-memory contact index (deviates from the `PhoneLookup` spec, can miss contacts saved seconds before a call; would need an ADR). Since Phase 5 the app's own time also leaves out the live lookup (step 10, after the local steps, with its own 800 ms budget and TC-LOOK-001); the blocking QA job runs without a server, so that step is a refused connection to 10.0.2.2 (17–41 ms observed) and is printed separately. It had pushed the app's own p95 to 51 ms in run 39035692047.
37. **Client address behind a proxy.** The per-IP OTP limit uses the socket address. Once a reverse proxy or TLS terminator sits in front of the server (Phase 15), configure trusted forwarded headers (Ktor `ForwardedHeaders`/`XForwardedHeaders` plugin, a new dependency to approve), or every client shares the proxy's limit.
38. **Local compose check used a host-built image.** In the agent sandbox Docker Hub returned 429 and the image build can't reach Maven Central, so the local `scripts/smoke.sh` run used the same runtime stage with a host-built distribution and skipped MinIO (a stale local image; MinIO is unused so far). The CI `compose smoke` job builds the real Dockerfile and runs the full stack and `scripts/smoke.sh`.
39. **`integrityToken`** is accepted by `/v1/auth/verify` (max 4 KiB) but not verified yet; Play Integrity verification belongs to the play-flavor hardening work.
40. **Access tokens can't be revoked early.** They are stateless JWTs valid 15 minutes; revoking a device's refresh chain stops new ones. A deny-list would be needed for instant logout (`DELETE /v1/me`, Phase 4 part 2 / Phase 8).
41. **SMS text** is English only and has no Android SMS Retriever app hash yet (needed for automatic code reading; add when the release signing key exists).
42. **Rotated refresh tokens** stay in `refresh_tokens` until they expire (needed to detect reuse); a cleanup job should delete expired rows (with the scoring/maintenance jobs).
43. **Concurrent refreshes** with the same token count as reuse and revoke the device. Resolved in Phase 5: `TokenAuthenticator` refreshes one at a time and reuses a token another request already refreshed (unit test).
44. **TC-API-004** now runs on `/v1/reports` (`ReportsApiTest`) as well as on the auth endpoints (resolved in part 2).
45. **Twilio docs.** `twilio.com` is blocked in the agent sandbox; the adapter follows Twilio's official API definition (`twilio-oai/spec/json/twilio_api_v2010.json`, operation `CreateMessage`). Before production, send one message with Twilio test credentials (`AC…` test SID, magic number `+15005550006`) and check the error-body handling.
46. **One code per number.** A new `/auth/start` replaces the pending code (3 per hour). A user who mistypes 5 times must request a new one, which counts against the same limit.
47. **Admin endpoints** (`POST /admin/jobs/{scoring|lists}`) are on the internal metrics port with a bearer token (`ADMIN_TOKEN`, unset = off); the "IP allowlist" of `rules.md` §7 is the port not being published. Add a real allowlist or separate admin auth before production (Phase 15).

The LightGBM blend is a later phase. Reporter trust stays 0.5 for everyone until trust updates exist (honeypots, Play Integrity, report history).
49. **Verified-business cap 0.39** sits just below the app's lowest threshold (LOW 0.4, issue 24) and the list threshold (`LIST_MIN_SCORE` 0.4); config refuses a cap at or above the list threshold. If LOW changes, change both.
50. **Bucket widths above 16 bits** (`architecture.md` §4.6 says 12–20) need a finer stored bucket column; 12–16 are served now.
51. **Registry deletions.** Resolved in Phase 9 for sender IDs, app hashes and verification ranges (`deleted_at` tombstones; rows come with `deleted`, the app removes them) and the business directory (`removed`). Open: a page holds at most 5,000 rows, and rows sharing one `updated_at` could straddle pages.
52. **Retention jobs** (reports 18 months, profile views 90 days, rotated refresh tokens; issue 42) don't exist yet.
53. **A report batch over the daily limit is refused whole** (429 + `Retry-After`). Resolved in Phase 5: the upload worker re-schedules itself after `Retry-After` and doesn't split batches.
54. **Unlisting has no undo** yet (a "list me again" setting belongs with profile settings, Phase 8). It hides user and business names; spam data stays.

60. **The alpha has no server.** Release builds get the server URL from `opencaller.apiBaseUrl`; v0.1.0-alpha ships without one (owner's choice), so sign-in, report upload, search, list updates and the live lookup show "Not connected to a server", and blocking works with the user's rules and settings. Reports stay in the outbox.
61. **TC-E2E-001 drives sign-in, report and sync through the debug QA receiver** (`QaOnline`), not the screens: the screens have unit tests, and typing an SMS code through UI automation on two emulators would make the job slow and flaky. The data path (outbox → API → scoring → list build → download → Room → engine) is the real one.
62. **The live lookup caches "not found" for 24 h.** A number reported after it rang once is caught by the next list update or after the cache expires (by design: few requests, nothing learned from repeats).
63. **"Test a number" runs the real engine**, so with a server it can make a live lookup (bucket id only, like a call).
64. **Bottom sheets opt in to `ExperimentalMaterial3Api`** (`ModalBottomSheet` in Compose Material 3 1.4). Revisit when Compose moves to 1.12+ (issue 3).
65. **The search quota is counted on the phone and on the server.** The phone's count is a display hint; the server's 429 is the authority (the indicator then shows 0 until `Retry-After`).
66. **Release signing** needs the four repository secrets (see Next step); without them the release workflow stops before building. CI builds the foss release unsigned on every push to catch release-only problems (lint vital).
67. **OkHttp is held at 5.4.0**: `okhttp-android` 5.5.0 needs compileSdk 37 (issue 3); move up together with compileSdk.
68. **Ringing is Telecom's.** OpenCaller doesn't declare `IN_CALL_SERVICE_RINGING`, so Telecom plays the ringtone and vibration as set in the system; both call notification channels are silent. Per-contact ringtones would need OpenCaller to ring itself (later).
69. **The ongoing-call notification is a plain notification** with Hang up, not `CallStyle.forOngoingCall` (meant for a call notification tied to a foreground service; the in-call service runs bound by Telecom). The status-bar call chip of Android 12+ therefore doesn't show; revisit with a `phoneCall` foreground service.
70. **Bluetooth before Android 14.** Without `BLUETOOTH_CONNECT` (not requested) device names can't be read, so the picker says "Bluetooth" and `setAudioRoute(ROUTE_BLUETOOTH)` uses the active headset; choosing between several headsets works from Android 14 (`CallEndpoint`).
71. **SIM chooser** (a call waiting in `STATE_SELECT_PHONE_ACCOUNT`): SIM names need `READ_PHONE_NUMBERS` on Android 12+ (`TelecomManager.getPhoneAccount`); without it the screen asks for it and always offers Cancel call, and never guesses a label. The dialer's own SIM picker (TC-DIAL-003) is 6b.
72. **TC-INCALL-002 / 003 need a phone with a SIM** (the emulator can't hold, merge or route to Bluetooth); the logic is unit-tested (`InCallStateTest`, `CallRegistryTest`, `InCallViewModelTest`), the device steps are in `docs/testing.md`.
73. **Calls placed by other apps.** Opening the in-call screen for a call another app placed relies on Android letting the in-call service start it; if a device refuses, the ongoing-call notification leads there. On the API 29 emulator an `ACTION_CALL` from the shell showed the in-call screen. The CI check (TC-DIAL-001) places the call from OpenCaller's own dial pad. On the API 36 emulator the emulated network ends every outgoing call at once: Telecom goes CONNECTING → DIALING, binds OpenCaller's in-call service, which opens the in-call screen, and then records `DisconnectCause REMOTE` (Telephony cause 2, NORMAL) with no hang-up from the app (run 39993877827). There the check accepts that sequence; staying on the call and Hang up are checked on API 29 and on a phone. Check `ACTION_CALL` from another app on a phone in 6b.
74. **TC-DIAL-003 / 004 are device-only** (the emulator has one SIM and no carrier): the logic is unit-tested (`DialPadViewModelTest`, `DialStringsTest`); steps in `docs/testing.md`. The dial pad's SIM picker needs `READ_PHONE_STATE` and, on Android 12+, `READ_PHONE_NUMBERS` (SIM names are never guessed); without them Telecom asks through the in-call SIM chooser.
75. **Quick replies:** the user's own list replaces Telecom's canned responses when it isn't empty (Telecom's are the system's, which the user edits in the system phone settings).
76. **6b UI and Robolectric tests run only in CI.** The sandbox can't resolve Compose or Robolectric (`dl.google.com` blocked), so the new screens, `DeviceCallLogTest` and `ContactWritesTest` were first compiled in CI; the view models, matcher, grouping and adapters were tested locally (JVM harness; adapters type-checked against the API 36 classes).
77. **Call log size.** The call log shows the latest 500 calls (provider `LIMIT`); older calls stay in Android's log. Deleting removes a whole group (one number, one day).
78. **Contacts from read-only accounts** (some sync adapters) can't be edited; Save then says so. New contacts are stored on the phone without an account. Photos, notes and other fields are kept on edit but not shown.
79. **T9 is Latin-keypad only** (ABC/DEF…, accents folded); names in other scripts match by their number only.
80. **MessageMeta covers SMS only.** Its key is the provider `_id`, and `Telephony.Sms` and `Telephony.Mms` number their rows separately, so MMS rows would collide. MMS get categories in 7b with a message-kind column (a Room migration).
81. **Group MMS and the user's own number.** Many SIMs don't store their number (`SubscriptionManager.getPhoneNumber` is empty). A received group MMS then keeps every recipient, the user included, and can land in a different conversation than one the user started with the same people. With a single recipient the message counts as sent to the user alone.
82. **MMS download** starts as soon as the notice arrives, also while roaming; there is no "auto-download" setting yet (later, with message settings).
83. **A failed MMS can't be resent** from the thread (write it again); failed SMS have "Tap to try again". Delivery reports are always asked for (no setting yet).
84. **Conversation list size.** The list reads the newest 5,000 SMS and 5,000 MMS rows (documented tables only, no undocumented thread table); conversations whose newest message is older don't show. A thread shows its newest 500 messages.
85. **TC-SMS-003 (MMS) is device-only:** the emulator has no MMS centre. The PDU codec, the store's row layout and the send/download flow are unit-tested or type-checked; the device steps are in `docs/testing.md`.
86. **Message notifications** show "Picture" for pictures (the system can't read MMS parts), have no conversation shortcuts or bubbles, and a reply from the notification goes out on the default SMS SIM.
87. **7a UI and Robolectric tests run only in CI** (as issue 76): the new screens, `MessagingDeviceTest`, `DefaultAppEligibilityTest` and `MainViewModelTest` were first compiled there; the pipeline, codec, address matching and view models were tested locally (JVM harness), the Android adapters type-checked against the API 36 classes.
88. **TC-SMS-002 on API 36:** the emulated network returns a delivery report (Delivered) but never delivers a message to the emulator's own number, so there the check ends at the delivery report; on API 29 the long message comes back and is checked whole (its parts joined).
89. **No trained SMS classifier.** The app classifies with rules (`RuleSmsClassifier`); the owner accepted the rule fallback for the beta (2026-11-02). The only corpus is generated from templates (`ml/sms-classifier/corpus/`), with made-up values and mostly invented brands, so `sms-classifier-train` refuses it. A model needs a collected corpus (messages donated with consent, anonymised on the device, a licence that allows training; ≥ 300 per class) and the LiteRT runtime, whose Android artifact and version could not be verified from the sandbox, so no LiteRT dependency was added.
90. **Corpus scores are optimistic.** 100 % OTP precision/recall and macro-F1 on every split (`docs/testing.md`) only show the rules handle the templates: the same person wrote the templates, the extractor and the rules, so the test split's formats were known while writing them. Real-message accuracy is unmeasured.
91. **Bank templates and brand domains are approximations.** `assets/ml/banks.json` imitates the shape of common alerts of the named banks, not copies of real messages; `assets/ml/brands.json` lists domains written by hand. Check both against real messages and the brands' sites before relying on them; US banks' short codes are deliberately not listed.
92. **The research section "Who is calling or texting, including OTP senders"** is not in the repository; 7b follows its summary in PRD F-ID-08 and architecture §4.4–4.5.
93. **Sender sources still missing:** self-registered names and community labels need a network lookup, which a message never triggers (architecture §4.4 step 2). Since Phase 9 a verified business's number names itself from the directory on the phone. The sender-ID registry, app hashes and verification ranges are still the example rows from `backend/server/seed/` until real extracts are imported (issue 109) and the hashes and ranges are curated in the admin web.
94. **OTP guard limits.** Calls are tracked in memory (a process restart forgets calls that ended); in screening-only mode the call state needs `READ_PHONE_STATE` on Android 12+ (issue 28), the other side is the call OpenCaller's screening service saw just before, and a call it didn't see (placed while screening is off) counts as a stranger. A missed call is never a conversation, so a flash call alone raises no warning.
95. **Full-screen warning.** `USE_FULL_SCREEN_INTENT` is the one the incoming-call screen already uses; on Android 14+ the user can turn it off (the warning is then a heads-up) and Play allows it for calling and alarm apps. The warning belongs to the call experience; recheck at Play review (Phase 15). The screen opens at once when OpenCaller has a window (in-call screen, caller-ID overlay), otherwise through the full-screen intent.
96. **Scheduled SMS** run on WorkManager, so Doze can delay one by a few minutes (exact alarms need a permission Play limits to clocks and calendars); one-to-one SMS only (no pictures, no groups), no editing, preset times only (no date picker yet).
97. **Known-bad links by hash prefix.** 32-bit prefixes of hosts and their parents, without a full-hash check (so no request ever reveals a link), stored in a small file instead of Room (no migration); the whole list is sent each time. Collisions are possible but rare with a small list; revisit with a larger list (full-hash confirmation through a k-anonymous request, like the live lookup).
98. **Smart inbox details.** A conversation's tab is the category of its newest classified message; MMS have no category yet (issue 80). OTP auto-delete checks every 6 hours, so a code can stay up to about 30 hours.
99. **7b UI and Robolectric tests run only in CI** (as issues 76 and 87): the new screens, `MessagingDeviceTest` additions, `RegistrySyncTest` and `feature:otp` were first compiled there; `core:ml`, the pipeline, resolver, OTP rules and the view models were tested locally (JVM harness), the Android adapters type-checked against the API 36 classes.
100. **OTP code on the lock screen.** Resolved in Phase 9 (owner's decision, 2026-11-02): the OTP notification is `VISIBILITY_SECRET`, so a secure lock screen shows nothing of it, whatever the user's setting (a private notification is shown in full under Android's default "Show all notification content"; seen on the API 29 emulator, run 41273807315). TC-OTP-008 checks it with the default setting and `dumpsys` (`vis=SECRET`).
101. **TC-INCALL-001 on the API 36 emulator lost the incoming call once** (run 41276075457, `c272653`): the in-call screen showed over the PIN lock screen with the caller card, but the call had ended (state 0) before Answer was tapped; the other run on the same commit and the re-run passed. `incall.sh` records Telecom's history only for the outgoing call, so the cause isn't known; if it repeats, record the incoming call's Telecom history at the Answer step.
102. **Room schema files.** Resolved in Phase 9. Until then CI's "Room schemas are committed" step compared the committed files with themselves: the build wrote no schema at all (`:core:database:copyRoomSchemas` NO-SOURCE in run 41311151805; nothing under `core/database/build` in run 41572058034). With AGP's built-in Kotlin, KSP 2.3.12 ignores `CommandLineArgumentProvider` arguments, which is how the Room Gradle plugin (and Room's documented provider) pass the schema folder; in run 41573673469 a provider still wrote nothing and `core:database:kspReleaseKotlin` came from the cache under the old key. The convention plugin now passes `room.schemaLocation` as a plain KSP option (not tracked as an input folder), adds `schemas/` to the androidTest assets, and the Room Gradle plugin is removed. The CI step removes the newest committed schema, re-runs `kspDebugKotlin` without incremental processing, fails when Room didn't write it back and prints Room's file when it differs. Run 41575163713 wrote `3.json`; the hand-written one differed only in its identity hash and final newline, and Room's file is committed. `2.json` stays hand-written (it can't be regenerated without version 2's code) and carries version 1's identity hash, which `MigrationTestHelper` doesn't use.
103. **Supporter check.** Resolved in Phase 10: `users.supporter_tier` is set from verified Play purchases (`POST /v1/billing/verify`, hourly re-check) or by hand; a self-hosted server (`SELF_HOSTED=true`) unlocks everyone without a badge (ADR 0006).
104. **Profile pictures stay on the profile.** The picture shows on My profile and on another number's profile, not on the caller card or in bucket entries (a URL per entry would make buckets large and every picture fetch would tell MinIO who is being looked at). Picture links are 15-minute pre-signed GETs to `MINIO_PUBLIC_ENDPOINT` (compose: `http://127.0.0.1:9000`, the emulator can't reach it); production needs a public HTTPS endpoint or a CDN (Phase 15). Pictures are re-encoded on the phone (JPEG, 512 px), but the server doesn't decode them; it checks size and type only.
105. **After `DELETE /v1/me`** the device's access token works on non-profile endpoints until it expires (≤ 15 minutes, issue 40); refresh tokens are gone. A report sent in that window is deleted with the account at the purge, and a search then records nothing (deleted viewers are skipped).
106. **Contact requests can't be withdrawn** by the requester, and an approval can't be revoked by the owner yet (both need a small endpoint and screen; later with profile settings, issue 54). Changing visibility away from Nobody makes the question moot.
107. **Profile and visitor screens run only in CI** (as issues 76, 87, 99): the view models, the badge mapping and the engine were tested locally (JVM harness); the screens, `ProfileRepository`, `AvatarScaler` and `MigrationTest` were first compiled there. The compose smoke (`scripts/smoke.sh` → Profiles) runs the picture upload through the real MinIO.
108. **No flash call for business claims.** A business proves control of its number with a 6-digit code by SMS or a Twilio voice call, not a flash call: Twilio calls only from our own verified numbers, a small pool would make the code guessable, and a missed call from a stranger is what OpenCaller teaches users to distrust (ADR 0005). Production needs `TWILIO_VOICE_FROM` for voice codes (unset: `voice` claims get 400); send one test call with Twilio test credentials before production (like issue 45).
109. **No registry access.** No documented, public access to the India DLT, Singapore SSIR, Australia ACMA or Ireland ComReg registries was found (owner's decision, 2026-11-02: CSV import plus placeholders). Findings from the sandbox (official sites were partly blocked, so re-check them): SGNIC publishes no public SSIR list or API; for ACMA's sender ID register no public search or bulk download could be confirmed; ComReg offers a status check for a sender ID's owner, not a public list; TRAI's sender-header lookup portal could not be verified. Each placeholder importer records `unavailable` in `import_runs` every day. A real importer replaces one only after its source is checked and tested.
110. **Play needs a privacy policy URL.** Play requires one for an app with SMS and Call Log permissions, also for closed testing. None is published yet (Phase 15: privacy policy and terms). `docs/release/play-data-safety.md` lists what it must cover. Owner to publish one before submitting the closed test.
111. **Store screenshots.** `fastlane/metadata/android/en-US/images/phoneScreenshots/` is empty: screenshots come from the emulator jobs' artifacts (`emulator-api-36` → `build/emulator/`, the light-mode tab walk), which the sandbox can't download (blob storage blocked). Owner: copy 4–6 of them there (or take them on a phone) before the F-Droid request.
112. **Phase 9 app code runs only in CI** (as issues 76, 87, 99, 107): the claim and business screens, `BusinessDirectoryRepository`, `DeviceClaimFiles`, `BusinessLogo`, the Room v3 migration and `BusinessDirectoryTest` were first compiled there; the view models, the engine and the resolver were tested locally (JVM harness).
113. **Name-source chips not everywhere yet.** Notifications (call, message, OTP) can't show a chip: their titles are plain text. The Contacts tab lists only the user's contacts, so its rows have no chip. Every other screen showing a name has one (caller card, call waiting, conversations and threads, call log, search, profiles, visitors, contact requests, business profile).
114. **Admin web has one shared account.** One user and password from the environment, behind the IP allowlist and CSRF tokens, with an audit log. Per-admin accounts, 2FA and the reverse proxy's trusted headers (issue 37) belong to Phase 15 hardening.
115. **F-Droid builds have no server address.** The F-Droid build compiles without `opencaller.apiBaseUrl`, so online features are off there; how a server address (official or self-hosted) reaches F-Droid builds needs a decision (a build-time property in the fdroiddata recipe, or a setting in the app).
116. **Verified-business numbers in other countries.** The phone keeps only its own country's directory, so a verified business calling from another country's number is recognised only by the live lookup (which needs no sign-in), not offline.
117. **Play setup by the owner.** TC-BILL-001 needs the Play Console subscription `opencaller_supporter` with base plans `supporter`, `gold` and `family` (the app maps a base plan to a tier by its ID's first word), license testers, a Google Cloud service account with Play Developer API access (`GOOGLE_PLAY_SERVICE_ACCOUNT_FILE`), `GOOGLE_PLAY_PACKAGE_NAME` and a `BILLING_ACCOUNT_SECRET` of at least 32 characters. For Drive backups: an OAuth client for the play signing key's SHA-1 and the `drive.appdata` scope on the consent screen.
118. **No real-time developer notifications.** Renewals, refunds and cancellations reach the server through the hourly re-check (`billing` job), so access can outlast a refund by up to an hour. Add Play RTDN (Pub/Sub push) if that matters.
119. **Family plan without sharing.** The `family` base plan gives its holder the supporter benefits; sharing with members belongs to the family feature (Phase 12, F-PR-14).
120. **Play Billing ktx not used.** The coroutine extensions' return types couldn't be checked from the sandbox (developer.android.com's reference for 9.x was not reachable), so `PlaySupporterStore` wraps the documented callback API itself.
121. **Backups.** Manual only (no automatic schedule); one Drive backup is kept (older ones are deleted after a new upload succeeds). Recordings are not in backups until recording exists (Phase 13). A forgotten passphrase can't be recovered. Message categories come back only for SMS found again by date and address while OpenCaller is the default SMS app; MMS categories don't exist yet (issue 80).
122. **Key derivation.** Backups use PBKDF2-HMAC-SHA256 (600,000 iterations, platform `javax.crypto`), not Argon2: no Argon2 library for Android was verified (it would need a native library). The file format records the iteration count, so it can be raised later.
123. **Messenger caller ID untested on a phone.** WhatsApp, Telegram and Signal change their notifications without notice; the parsing is unit-tested against the documented `CATEGORY_CALL` / `CallStyle` markers. No app version has been tested on a device yet (`docs/testing.md`, TC-UT-004).
124. **Ghost Call timing.** WorkManager can ring a few seconds to minutes late in Doze; exact alarms need `SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM`, which Play limits to clocks and calendars. On Android 14+ the user can turn off full-screen intents; the fake call then shows as a heads-up.
125. **Donation link** comes from `opencaller.donationUrl` at build time; none is set yet (the foss Supporter screen then says "This build has no donation link" and explains that a self-hosted server unlocks everything). The owner chooses the donation page.
126. **Room 4.json** is Room's own file once CI's schema step prints it; until then the committed file is provisional (as for 3.json in Phase 9, issue 102).
127. **Phase 10 app code runs only in CI** (as issues 76, 87, 99, 107, 112): the screens, Play Billing, Drive, the Robolectric tests (`BackupTest`, `GhostCallTest`, `AnnounceCallerTest`, `SpamListSyncTest` additions, `MigrationTest` 3→4) were first compiled there; `core:phonenumber` (`findInText`) and the backend were tested locally.
